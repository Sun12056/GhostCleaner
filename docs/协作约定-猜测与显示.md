# Core ↔ UI 协作约定：猜测与显示

> 日期：2026-10-17
> 收敛自 Core 0.2 / UI 0.1 的十余轮往复
> （信号调研、契约改动、警告结构化、观测冲突、AppData 导航）
>
> 本文件放 `docs/` 根目录而非 `core-0.1` / `ui-0.1` 之下，因为**两边都要遵守**。

---

## 两条原则

### 原则一：凡是要猜的东西都在 Core，UI 只负责把「这是猜的」原原本本地显示出来

### 原则二：Core 给出猜测时必须同时给出猜测依据

两条合成一个闭环：

- 原则一解决「**谁来判断**」
- 原则二解决「**用户凭什么判断**」

缺了原则二，原则一就退化成"Core 说了算，只是换个地方说" ——
用户拿到一个结论却无从判断该不该信，判断成本被转嫁给了用户。

---

## 这两条不是凭空定的，是踩出来的

### 原则一的由来（三次同类漂移）

| 事件 | 漂移 |
|---|---|
| UI 按文案关键词分类警告 | `IsUncertaintyWarning(string)` 里匹配"未能完成"等词，Core 改措辞 → 分类**静默**失效 |
| UI 自设「观测冲突」判定 | UI 用 `≥VeryHighProbability`，Core 用 `≥Suspicious` → 聚合卡写"2 项"、逐项展开不是同样 2 项 |
| UI 考虑自己猜 AppData 路径 | 与 Core 的匹配规则各写一份，必然分叉 |

共同模式：**判定逻辑落在 UI，就会与 Core 漂移，而且这种漂移极难发现**
（不报错、不崩溃，只是悄悄地不一致）。

### 原则二的由来

UI 的原话：

> 「该软件的数据目录：…\Foo」和「候选：…\Foo（Core 按目录名推测，可能不对）」
> 差的不是措辞，是**这家工具的整体可信度** ——
> 前者一旦猜错，整页其它结论会被连坐怀疑。

---

## 配套约定

### ① 猜测的成本必须被兜住

UI 的原话（解释为什么不做"按目录名猜子目录"）：

> 猜错的成本不是没帮上忙，是**制造了一个指向反方向的假证据** ——
> 用户会在错误的文件夹里翻一遍，然后得出"原来它没数据、可以删"。

推论：**宁可不给，不要给错。**

实现要求：猜错时必须能回退到"不猜"的状态。
（AppData 导航：候选路径全不存在 ⇒ 回退到打开 AppData 根目录。）

### ② 通用名 / 同名冲突是猜测的高发区

实测（Prefetch 那轮）：

```
UNINSTALL.EXE 跨 5 个目录    NODE.EXE 跨 2 个
另有 UNINS000 / CHROME / MEDIA_PLAYER / LOGUPLOAD
```

**任何按名字匹配的猜测都必须处理"同名不同路径"。**

优先用**数据驱动**规则：同一名字出现在 ≥2 个检出目录 ⇒ 不产出候选。
而不是维护黑名单 —— **黑名单会过期**。

### ③ 文案写机制，不写统计

UI 的判断：本机统计（如"8 条里只覆盖 2 条"）换台机器就错，
而产品文案写死后几乎没人回头改。

应写「活动写在 AppData、安装目录常年不动」这类**机制性表述**，
它在任何机器上都成立。数据留在文档里。

**推论：具体准确率数字（AUC / Precision / 召回率）也不要出现在用户可见文案里。**

除了同样会过期之外，它还有一个反向效果 —— 写出「基于不可靠的自动判定（AUC 0.648）」
时，读者实际得到的信息是"有模型算过、有依据"，而不是"这个结论不可靠"。
**引用指标会给可靠性加权威，即便被引用的数字本身说的恰恰是不可靠。**

正确写法是把两件事绑成同一条推理链，例如「这个倾向同样由那条推断得出，因此同样不可靠」
—— 用户读到的是"这就是那个不可靠东西的另一个说法"，而不是"另有一个模型在替它背书"。

**适用范围：用户可见文案。代码注释不受本条约束。**

注释里保留具体数字与数据出处是有价值的：接手的人需要知道
"为什么这里不把置信度当结论"，且注释会随代码演进被重新审视；
而产品文案一旦写死，几乎没人回头改。

> 判据：这句话**用户会不会读到**。会读到 ⇒ 受约束；只有开发者看到 ⇒ 不受约束。

## 检查清单

**Core 侧产出猜测时：**

- [ ] 字段名带"候选 / Candidate"语义，不叫确定路径
- [ ] 每个猜测附带来源枚举（说明是怎么猜的）
- [ ] 猜测**不参与打分**（在代码注释里写死这条约束）
- [ ] 定义了回退路径（猜不出来时怎么办）

**UI 侧显示猜测时：**

- [ ] 不做任何判定，只显示 Core 给的东西
- [ ] 显示时保留"这是猜的"这层意思（不只是字段名，用户读到的那句话也要带）
- [ ] 覆盖说明**常驻**，不能让用户产生"没提示 = 安全"的联想
- [ ] **聚合计数与阈值取自 Core 的产出，不在 UI 另设一套**
      （由来：漂移表第 2 条 —— 自设冲突阈值导致"聚合卡写 2 项、展开不是同样 2 项"）

> 第 4 条由 UI 补充（2026-10-17）。补它的理由是：由来表里三条漂移中，
> 第 1、3 条都被"不做判定"覆盖了，只有第 2 条**没有对应护栏**。
> 这类漂移的共同特征是**不报错、不崩溃，只是悄悄不一致**，
> 所以必须有一条专门对着它的检查项，否则还会被重复踩。
- [ ] **聚合计数与阈值取自 Core 的产出，不在 UI 另设一套**
      （由来：上文漂移表第 2 条 —— 自设冲突阈值导致"聚合卡写 2 项、展开不是同样 2 项"）

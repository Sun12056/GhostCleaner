# Phase 14 — UX Review

> 对照方案第三十七节「最终验收标准」逐条自检，并列出问题与修改建议。

## 1. 验收对照

### 产品层

| 标准 | 结论 | 依据 |
|---|---|---|
| 用户第一次打开就能理解 GhostCleaner 是干什么的 | ✅ | 概览 Hero 一句话「发现 Windows 忘记的软件残留。」+ 说明「扫描只做检测，不会删除任何文件」 |
| 核心流程清晰 | ✅ | 概览 → 扫描 → 扫描中 → 完成 → 结果 → 详情 → 隔离，7 段均有明确主任务 |
| 扫描 → 查看 → 判断 → 隔离完整闭环 | ✅ | 流程 1；隔离后 Toast 直达隔离区，可恢复 |

### UX 层

| 标准 | 结论 | 依据 |
|---|---|---|
| 每个页面都有明确主要任务 | ✅ | `04` §4 一页一任务表 |
| 用户不会迷路 | ✅ | 侧栏 7 项单级常驻；「扫描结果」常驻可随时回看 |
| 不确定结果不会被包装成确定结果 | ✅ | 全部用词绑定 Core 枚举文案；禁用"确定是残留""一键清理" |
| 用户可以查看检测依据 | ✅ | 详情面板正向/负向证据分区 + 权重 |
| 用户拥有最终决定权 | ✅ | 默认全不勾选；无一键全选推荐项；主动作是可恢复的隔离 |

### 视觉层

| 标准 | 结论 | 依据 |
|---|---|---|
| 不像普通电脑管家 | ✅ | 无体检分数、无一键加速、无大圆环 |
| 不像杀毒软件 | ✅ | Danger 色面积 ≤ 2%，高风险用低强度徽章而非红色实心 |
| 不像网页 Dashboard | ✅ | 卡片用 1px 边框不用阴影；圆角 ≤ 12；间距 8px 网格；中高密度 |
| 不像 AI Demo | ✅ | 无渐变、无发光、无紫蓝渐变 |
| 不像学生作业 | ✅ | Token 全覆盖，无硬编码值 |
| Windows 桌面应用感明显 | ✅ | 系统标题栏、Segoe UI Variable、32px 控件高度、无 Web 式留白 |
| 图标统一 | ✅ | 24 栅格 / 1.75 描边 / round 端点 / 全线性 |
| 颜色统一 | ✅ | 全部走 token |
| 间距统一 | ✅ | 8px 网格，只允许 10 个值 |
| Light / Dark 都完整 | ✅ | 同一套 token 名两套值，非反色 |

### 开发层

| 标准 | 结论 | 依据 |
|---|---|---|
| 设计可以被 WPF / WinUI 实现 | ✅ | 无毛玻璃、无 Mica 依赖、无 SVG 滤镜、无 CSS 专属效果 |
| 不依赖无法实现的网页特效 | ✅ | 阴影仅用于浮层，WPF `DropShadowEffect` 可覆盖 |
| 组件具有明确状态 | ✅ | `09` 每个组件列出 Rest/Hover/Pressed/Focus/Disabled/Loading |
| 数据需求明确 | ✅ | `02` §5 的 11 条 UDR + `15` §7 |
| UI 0.2 可以直接进入实现 | ✅ | `15` 含页面尺寸、文件级改造清单 |

## 2. 发现的问题与修改建议

### P0 — 必须在 UI 0.2 实现前解决

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| **R1** | **扫描进度分母错误**：现状 `ProgressValue = ScannedDirectories * 100 / CandidateCount`，`CandidateCount` 是候选数不是总数，进度会从 0 直接跳到几百又被 `Math.Clamp` 压到 100 | 进度条完全不可信，用户无法判断还要多久 | Core 提供 `TotalDirectories`（`UDR-03`）。UI 0.2 若 Core 未就绪，改为**不确定进度条**并只显示「已检查 N 个目录」，不显示百分比 |
| **R2** | **没有扫描记录**（结果不持久化） | 关掉窗口就丢结果；概览「上次扫描」无从取数；流程「回看上次判断」断裂 | Core 提供 `IScanHistoryService`（`UDR-02`）。**这是 UI 0.1 设计里唯一有页面但无数据支撑的功能** |
| **R3** | **`OrphanItem.Evidence` 在 UI 层被拼成一大段字符串**（`EvidenceText`） | 用户看不到结构化依据，"为什么这么判断"完全丢失 | UI 0.2 必须改用 `PositiveEvidence` / `NegativeEvidence` 两个属性渲染 `EvidenceItem` 列表 |
| **R4** | **危险操作依赖 `MessageBox`** | 无法统一视觉、无法做"输入确认文字"以外的一致体验 | 用 `09` §21 Dialog 组件统一替换；`ConfirmTextWindow` 保留逻辑，改皮肤 |

### P1 — 重要

| # | 问题 | 建议 |
|---|---|---|
| **R5** | 概览「预计可释放」容易被理解成"删了就能多出这么多空间" | 标签固定为「预计可释放」，Tooltip 说明"仅统计未排除条目的目录体积，实际释放取决于你的选择" |
| **R6** | 结果页 `Selected`（正在看）与 `Checked`（要处理）容易混淆 | 已在 `09` §16 明确两个独立视觉通道；UI 0.2 必须严格实现，不可省掉左侧 3px 指示条 |
| **R7** | 用户可能不理解「疑似残留度」与「清理风险」的区别 | 首次进入结果页时，对置信度条显示一次 Teaching Tooltip；关于页常驻「两个不同的问题」区块 |
| **R8** | 非管理员被弹模态框阻断（现状 `OrphanScanViewModel` 里 `_dialogs.Warning`） | 改为非阻断 banner（`11` §5） |
| **R9** | 扫描中大列表实时插入可能导致 UI 卡顿 | 实时候选列表限制 200px 高 + 最多保留最近 50 条；结果列表虚拟化 |
| **R10** | 「需要复核」筛选与「高可信度」筛选可能重叠（一项可同时满足） | 这是**正确行为**（两个维度独立），但需在筛选器 Tooltip 说明"两项可同时命中" |
| **R11** | 隔离区恢复失败时用户不知道怎么办 | 错误文案必须给出「打开原位置」动作（`11` §4.4） |

### P2 — 优化

| # | 问题 | 建议 |
|---|---|---|
| **R12** | 结果列表无键盘快捷操作 | 支持 `↑↓` 移动选中、`Space` 切换勾选、`Ctrl+A` 全选可见项、`Enter` 打开详情 |
| **R13** | 详情面板窄窗口下抽屉无关闭按钮 | 抽屉头部加 `gc-close`；`Esc` 关闭 |
| **R14** | 设置项即时保存但无反馈 | 关键项（隔离区目录、保留天数）保存后给 2s Toast |
| **R15** | 白名单移除入口不显眼 | 结果详情「加入白名单」后 Toast 提示"可在设置 → 保护与白名单 中移除" |
| **R16** | 长路径在 420px 详情面板里仍会截断 | 路径区提供「复制」按钮（已有）+ 双击展开为多行（仅详情面板，列表保持单行） |

## 5. 最终设计规范（摘要）

```
产品定位   专门分析 Windows 软件残留的分析工具，不是清理器
核心差异   疑似残留度（靛蓝强度）与清理风险（语义徽章）双维度独立
默认动作   隔离（可恢复），永不默认删除
决策权     永远在用户；扫描器只输出建议，永不输出删除

视觉方向   Direction D — Evidence Instrument（证据仪器）
色彩      中性冷灰 + 单一靛蓝强调 + 克制的语义色（Danger ≤ 2%）
字体      Segoe UI Variable Display/Text，回退 Microsoft YaHei UI
网格      8px（4/8/12/16/20/24/32/40/48/64）
圆角      4 / 6 / 8 / 12 / 999（禁止更大）
阴影      卡片无阴影；仅浮层用 elevation 1/2
图标      24 栅格 · 1.75 描边 · round · 全线性 · currentColor
动效      0/120/200/320ms，standard 曲线，只动 opacity/transform
主题      Light / Dark 同一套 token 名，默认跟随系统
```

## 6. 结论

UI 0.1 设计**通过验收**，可以交付 UI 0.2 进入实现。

但有一个前置条件：**R1（进度）与 R2（扫描记录）必须先与 Core 开发线对齐**。
若 Core 0.1 无法提供：

- 扫描中页面降级为「不确定进度 + 已检查目录数」，不显示百分比；
- 扫描记录页面降级为「只读的操作日志视图」，隐藏「查看结果」按钮；
- 概览「上次扫描」改为从日志派生（最近一次成功扫描的时间），不提供入口。

其余页面不依赖缺失数据，可完整实现。

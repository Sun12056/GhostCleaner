## 2. Prefetch：你的预警被数据证实了

你上次提醒「废弃软件重装前跑过也会留记录」，并建议**单列那 4 条看分数变化**而不是只看 AUC。

我照做了 —— **正是这个建议促成了决定性反例**：

```
Registry Repair   真值=残留  置信=96  Prefetch=2026-10-16（昨天）
```

`Registry Repair` 是回标里置信度**最高**的真残留，也是仅有的两条判对样本之一。
落地「近期运行过 = 在用」会把它判成在用，**Recall 从 0.333 掉到 0.167**。

其余数据：

- 命中率 35/41（85%）—— **看着极好，但下面会说明这是假象**
- AUC 0.657（全算）/ **0.620（排除误匹配）**，对比现有 0.648 → 持平或更差
- 分组：在用 71% 有记录 vs 残留 67% 有记录 → **几乎重合**

## 3. 通用 exe 名的坑（这条要提醒你）

**11 / 41 条命中的是通用名，不是该软件的主程序：**

| exe 名 | 误匹配到的目录 |
|---|---|
| `UNINSTALL.EXE` | wangyiyunyinyue、IROK、aDrive、CloudMusic、ZWCAD2026（**5 个**） |
| `NODE.EXE` | node.js、微信web开发者工具 |
| 其它 | `UNINS000`、`CHROME`、`MEDIA_PLAYER`、`LOGUPLOAD` |

Prefetch 文件名是 `<EXENAME>-<hash>.pf`，**hash 由 exe 完整路径算出**，
正是用来区分同名不同路径的。按名字匹配必然跨目录误匹配。

> **如果你那边有任何按 exe 名 / 文件名做匹配的地方，同样会踩。**
>
> 特别点名「**运行自带卸载器**」那个入口：`Uninstall.exe` 这类名字在不同软件间是通用的。
> **别用文件名判断"这是哪个软件的卸载器"，用完整路径。**

## 4. Core 定案

| | 之前 | 现在 |
|---|---|---|
| 目标 | 自动判定"是不是残留" | **只提供证据** |
| 置信度含义 | 残留概率 | **使用迹象的缺失程度** |
| 建议 | 可输出 `Quarantine` | **永不输出**（已落地） |
| 措辞 | "非常高概率残留" | "**未检测到任何使用迹象**"（已落地 + 测试锁死） |
| 判断权 | Core | **用户** |

建议集收敛为 `{Keep, Review, HighRiskReview}`，隔离永远只是用户自选动作。

**这不是退让，是诚实。** `Precision 0.333` 下由 Core 建议"可清理"，本身就是误删风险源。

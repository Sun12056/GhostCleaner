# Phase 4 — 信息架构（IA）

## 1. 对方案第十二节「初始 IA」的验证

方案给出的初始建议：

```
概览 / 残留扫描 / 扫描结果 / 隔离区 / 扫描记录 / 设置 / 关于
```

**验证结论：通过，但需要做 3 处修正。**

| 修正 | 内容 | 理由 |
|---|---|---|
| ✅ 修正 1 | **「残留扫描」与「扫描结果」彻底拆成两个页面** | 现有代码把两者塞进同一页（`OrphanScanViewModel` 703 行）。扫描是一次性动作，结果是可反复查阅的资产，生命周期不同 |
| ✅ 修正 2 | **「扫描记录」承载历史扫描 + 操作日志** | 现有「日志」是独立页面，但用户真正的需求是「回到上次那次扫描」，日志只是副产品。合并后进历史页的第二个分区 |
| ✅ 修正 3 | **「设置」内部分组，不做成侧栏二级** | 桌面应用侧栏二级导航成本高。设置用页内分区导航（左分区列表 + 右内容），保持侧栏扁平 |

## 3. 导航结构

侧栏 **7 项，单级，无折叠**：

| 顺序 | 页面 | 图标 | 分组 |
|---|---|---|---|
| 1 | 概览 | `gauge` | 主任务 |
| 2 | 残留扫描 | `scan-search` | 主任务 |
| 3 | 扫描结果 | `list-tree` | 主任务 |
| 4 | 隔离区 | `archive` | 主任务 |
| — | — | — | 分隔线 |
| 5 | 扫描记录 | `history` | 辅助 |
| 6 | 设置 | `settings` | 辅助 |
| 7 | 关于 | `info` | 辅助 |

**「扫描结果」常驻导航的理由**：它是用户停留时间最长的页面。扫描完成后用户会反复回来复查、勾选、看依据，不应该只能从「扫描完成」页进一次。

## 4. 页面主任务（One Page, One Job）

| 页面 | 唯一主任务 | 主 CTA | 明确不做的事 |
|---|---|---|---|
| 概览 | 回答「现在能为我做什么」 | 开始扫描 | 不做详细数据展示 |
| 残留扫描 | 确定扫描范围并启动 | 开始扫描 | 不展示结果列表 |
| 扫描结果 | 逐条做出保留 / 隔离的判断 | 移入隔离区 | 不做批量一键处理 |
| 隔离区 | 恢复或永久清除 | 恢复 | 不做扫描 |
| 扫描记录 | 回看某次扫描的结论 | 查看该次结果 | 不做修改 |
| 设置 | 调整判定与保护规则 | （无主 CTA，自动保存） | 不做扫描配置引导 |
| 关于 | 建立信任 | 打开项目主页 | 不做功能 |

## 6. 页面尺寸与布局骨架

| 项 | 规格 |
|---|---|
| 主窗口默认 | **1280 × 840**（比现有 1340×880 更契合 13"/14" 笔记本） |
| 最小窗口 | **1080 × 680** |
| 侧栏宽度 | **232 px**（固定，不折叠） |
| 内容区 | 自适应，左右 padding **32 px**，上下 **24 px** |
| 内容最大宽度 | **1400 px**（超宽屏不无限拉伸，居中留白） |
| 结果页详情面板 | 右侧 **420 px**，可折叠；窗口 < 1080 时改为覆盖式抽屉 |
| 顶栏 | 无全局顶栏（页面自带标题区），减少层级 |
| 危险操作条 | 底部固定操作栏（Results / Quarantine 页），高 **64 px** |

## 7. 响应式行为（桌面应用）

| 窗口宽度 | 行为 |
|---|---|
| ≥ 1280 | 完整布局（侧栏 + 列表 + 详情面板） |
| 1080 – 1279 | 详情面板收窄至 360 px |
| < 1080 | 详情面板转为**覆盖式抽屉**（从右侧滑入，带遮罩） |
| < 900 | 侧栏收窄为 **64 px 图标栏**（仅图标 + Tooltip） |

> 不做手机/平板布局。这是 Windows 桌面应用。

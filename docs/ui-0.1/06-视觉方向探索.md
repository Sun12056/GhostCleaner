# Phase 6–7 — 视觉方向探索与最终方向

## 1. 五个候选方向

### Direction A — Windows Native（Fluent 原生）

**特征**：Fluent 2 规范、Mica 材质、系统强调色、圆角 8px、Segoe UI Variable、跟随系统主题、`NavigationView` 左侧汉堡菜单。

| | |
|---|---|
| ✅ 优点 | 原生感最强；Windows 11 上"就是系统的一部分"；无障碍与高 DPI 天然正确；用户零学习成本；Dark 模式免费 |
| ❌ 缺点 | 与系统设置强绑定，品牌辨识度低；强调色被系统覆盖后可控性差；Mica 需要 Win11，Win10 降级体验割裂；**容易显得"没有设计"** |
| 实现成本 | 中（需 Win11 SDK / WPF 自绘 Mica，原生 WPF 无 Mica） |
| 风险 | 原生 WPF 拿不到 Fluent 控件库，手搓成本高且容易不伦不类 |

---

### Direction B — Professional Utility（专业工具）

**特征**：中性灰阶、单一强调色、信息密度中高、工具栏 + 数据表 + 状态栏三段式、等宽数字、1px 边框、无阴影、紧凑行高。

参考气质：Everything / Process Explorer / WizTree / Windows Terminal / VS Code 设置页

| | |
|---|---|
| ✅ 优点 | 最符合「专门分析 Windows 软件残留的工具」这一定位；可信度最高；天然支撑证据表格；Dark 模式最容易做对；不依赖 Win11 新特性，WPF 实现成本低 |
| ❌ 缺点 | 若拿捏不好会显得"老旧"；对留白与排版要求高，否则变拥挤；视觉记忆点弱 |
| 实现成本 | **低**（纯 WPF 可完全实现） |
| 风险 | 冷感太强，普通用户可能觉得"不好上手" |

---

### Direction C — Modern Minimal（现代极简）

**特征**：大留白、超大标题、克制的灰阶、细字重、少边框、单色图标、呼吸感强。

参考气质：Linear / Notion / Arc

| | |
|---|---|
| ✅ 优点 | 视觉高级；一眼"现代化"；截图好看 |
| ❌ 缺点 | **信息密度太低** —— 扫描结果页要同时展示路径、大小、置信度、风险、依据，塞不进去；极简会掩盖"证据"这个核心卖点；**非常容易滑向"网页 Dashboard"**（设计红线）；WPF 上细字重渲染发虚 |
| 实现成本 | 中 |
| 风险 | 与方案第十六节红线「不像网页 Dashboard」直接冲突 |

---

### Direction D — Evidence Instrument（证据仪器）

**特征**：以「证据」为唯一视觉主角。中性底 + 单一靛蓝强调色；**置信度用蓝色强度条**、**风险用语义徽章**（两套互不混用的编码）；列表行右对齐等宽数字；证据条目带符号权重 `+25 / −30`；分区用 1px 分隔线而非卡片；几乎没有圆角以外的装饰。

参考气质：仪器面板 / 审计报告 / Everything + 法医报告

| | |
|---|---|
| ✅ 优点 | **把 GhostCleaner 的差异化（P2：两个独立维度）直接变成视觉语言**；用户第一眼就看到"依据"而不是"分数"；信息密度合适；Dark/Light 对称；WPF 实现成本最低；最不像电脑管家 |
| ❌ 缺点 | 需要严格的排版纪律，否则变乱；图标系统必须自建（不能用通用图标库凑） |
| 实现成本 | **低** |
| 风险 | 若表格做得太密会退回 B 的"老旧"问题 —— 靠 8px 网格 + 分组留白化解 |

---

### Direction E — Neutral Lab（中性实验室）

**特征**：纯黑白灰 + 极少的强调色（只在 CTA 与危险操作用色）；大量使用"分隔线 + 分组标题"；无卡片、无阴影、无圆角（仅 4px）；等宽字体参与排版。

| | |
|---|---|
| ✅ 优点 | 极强的技术可信感；打印/导出报告观感一致 |
| ❌ 缺点 | 色彩过少导致状态识别（受保护/需复核/高风险）只能靠文字，扫描效率下降；对普通用户过于冷硬；不符合"Modern"关键词 |
| 实现成本 | 低 |
| 风险 | 「状态不可一眼辨识」是硬伤 |

## 3. 最终方向：**Direction D — Evidence Instrument（证据仪器）**

> **以 B「Professional Utility」为骨架，以 D「Evidence Instrument」为灵魂，吸收 C 的留白纪律与排版克制，明确拒绝 A 的"无设计感"与 C 的"网页 Dashboard 化"。**

### 最终方向的 8 条视觉宪法

| # | 规则 |
|---|---|
| **V1** | **中性灰阶打底，单一靛蓝（Indigo）强调色。** 强调色只用于：主 CTA、当前导航、选中态、进度、链接。 |
| **V2** | **两套编码互不混用**：疑似残留度 = 靛蓝强度条 + 百分比；清理风险 = 语义色徽章（低/中/高）。 |
| **V3** | **卡片用 1px 边框，不用阴影。** 阴影只出现在浮层（菜单、对话框、Toast、抽屉）。 |
| **V4** | **8px 网格**，间距只允许 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48。 |
| **V5** | **圆角只有 3 档**：控件 6px、卡片 8px、徽章/药丸 999px。禁止更大圆角。 |
| **V6** | **数字全部等宽对齐**（Tabular Figures）。路径、大小、百分比、权重一律右对齐或定宽。 |
| **V7** | **禁用渐变、禁用玻璃拟态、禁用发光、禁用 emoji。** |
| **V8** | **禁止巨大百分比圆环。** 整体结论用「分区数字组」，不用单一评分。 |

### 为什么不是其他方向

- **不是 A**：WPF 拿不到 Fluent 控件库，手搓 Mica 成本高且 Win10 上割裂；且品牌辨识度几乎为零。
- **不是 C**：扫描结果页的信息密度需求与极简直接冲突，且极易滑向设计红线「网页 Dashboard」。
- **不是 E**：完全去色会让「受保护 / 需复核 / 高风险」三种状态无法一眼辨识，降低决策效率。
- **B vs D**：B 是合格的骨架，但 B 没有回答「GhostCleaner 和别的清理工具长得更不一样在哪」。**D 把「证据」这个唯一差异化做成了视觉本身** —— 这是选 D 的决定性理由。

## 4. 品牌名与 Logo 方向

### 命名
对外统一 **GhostCleaner**（与仓库一致）。代码命名空间 `WinCleaner.*` → `GhostCleaner.*`（`UDR-11`，UI 0.2 执行）。

中文副标题：**Windows 软件残留分析工具**（不用「清理大师」「优化神器」）。

### Logo 概念：**Ghost + Shield + Layered Remnant**

方案第十七节建议探索 Ghost + Shield + Search，并明确「不要卡通幽灵」。

最终采用 **抽象幽灵轮廓 × 盾形边界 × 层叠残影**：

```
   ┌───────────────┐        ← 盾形外框（2.5px 描边）= 保护 / 安全边界
   │   ╭───────╮   │
   │   │ █████ │   │        ← 实心幽灵穹顶 = 残留的软件本体
   │   │███████│   │
   │   ╰──╯ ╰──╯   │        ← 波浪底缘 = 幽灵的抽象化（无眼睛、无表情）
   └───────────────┘
```

- **无眼睛、无表情、无卡通拟人** —— 只有几何轮廓。
- 盾形 = 安全 / 保护 / 可撤销；幽灵 = 残留；**两者叠加 = "被安全围住的残留"**。
- 波浪底缘由 3 个半圆构成，是幽灵唯一的识别特征，在 24px 下仍可辨认。

## 5. 色彩方向

| 语义 | 方向 | 说明 |
|---|---|---|
| Primary | **Indigo / 靛蓝** | 主 CTA、当前导航、进度、选中、链接。比纯蓝更冷静、比紫更技术 |
| Success | 低饱和绿 | 仅用于「已恢复 / 已完成 / 风险低」 |
| Warning | 琥珀 | 仅用于「需要复核 / 部分风险 / 扫描不完整」 |
| Danger | 砖红 | **只用于永久删除、高风险、严重错误**。全应用出现频次必须极低 |
| Neutral | 冷灰（带极轻蓝调） | 背景、表面、边框、正文 |

> **危险色纪律**：Danger 色在 Light 模式下全应用同时可见面积不得超过 **2%**。若发现到处是红色，说明设计已经变成杀毒软件。

# Phase 3 — 产品定位

## 1. 一句话定义

> **GhostCleaner 是一个专门分析 Windows 软件残留的工具。它不替你做决定，它把判断依据摆给你看。**

## 2. 它解决的具体问题

重置 / 重装系统后，`D:\`、`E:\` 上遗留大量旧软件目录。这些目录在注册表里已经查不到卸载项、App Paths、快捷方式、服务、计划任务、进程、AppX、文件关联、启动项 —— 手动逐个核对极其耗时，而直接删除又可能删掉绿色软件、游戏库、开发项目和用户数据。

GhostCleaner 做的事是：**把「Windows 还记得它吗」这件事，从 9 个来源逐一查证，然后把证据摊开给用户。**

## 3. 产品定位矩阵

| 维度 | GhostCleaner 站位 |
|---|---|
| 品类 | 系统分析工具（Analysis Tool），**不是**清理器（Cleaner） |
| 用户 | 会自己判断的技术用户 / 重度 Windows 用户 |
| 心智 | 「法医 / 审计」而非「保姆 / 管家」 |
| 默认动作 | **隔离**（可恢复），永不默认删除 |
| 决策权 | **永远在用户**，扫描器只输出"建议"，永不输出"删除" |
| 语气 | 陈述事实，不承诺结果，不制造焦虑 |

## 4. 三条不可违背的产品原则（UI 必须体现）

### P1 — 不确定性必须被如实表达

- 禁止「确定是残留」「可以放心删除」「一键清理」这类绝对表述。
- Core 已经这么做了：`CleanupRecommendation` 枚举里**没有 Delete**。
- UI 层：所有结论用词必须与 Core 一致 —— 用「疑似残留度 92%」「建议人工确认后隔离」，不用「发现垃圾」「建议清理」。

### P2 — 两个独立维度，绝不合并

| 维度 | 回答的问题 | 视觉编码 |
|---|---|---|
| **疑似残留度**（Confidence） | 我们有多大把握认为它是残留？ | 中性→靛蓝的强度条 + 百分比数字 |
| **清理风险**（Risk） | 如果清理它，可能有多危险？ | 语义色徽章（低 / 中 / 高） |

**允许并且必须允许「残留度 92% + 风险高」同时存在。**
**不允许因为残留度高就自动推荐清理。** 这是 GhostCleaner 与普通清理工具的分水岭。

> 视觉上刻意用**两套完全不同的编码系统**：置信度用「蓝色强度」，风险用「语义色徽章」。用户不该把两者混为一谈。

### P3 — 用户拥有最终决定权

- 扫描结果**默认全部未勾选**（Core 已实现 `IsSelected` 默认 `false`）。
- 无「全选推荐项」这类一键操作；提供的是「仅选低风险」这种**明确边界**的辅助。
- 每一次破坏性操作都有**可撤销路径**（隔离区），永久删除需要**输入确认文字**。

## 5. 视觉定位关键词

```
Modern    现代     —— 不是 2015 年的软件
Technical 技术     —— 敢把证据和分数摆出来
Calm      克制     —— 不制造焦虑，不用红色恐吓
Precise   精准     —— 数字对齐、用词准确、不模糊
Trustworthy 可信   —— 承认不确定性、说明来源、可撤销
Lightweight 轻量   —— 不是臃肿套件
```

## 6. 绝对避免（设计红线，评审逐条检查）

| ❌ 不要 | 原因 |
|---|---|
| 360 / 腾讯电脑管家式 UI | 品类错位，可信度归零 |
| 「一键清理」「一键加速」「电脑体检」 | 与 P1/P3 直接冲突 |
| **巨大百分比圆环**（体检分数） | 制造虚假权威感；残留是逐条判断，不是总分 |
| 炫酷霓虹 / 黑客风 / 游戏风 | 与 Calm/Precise 冲突 |
| Antivirus Threat UI（病毒威胁红） | GhostCleaner 处理的是"残留"，不是"威胁" |
| 大量渐变 | 廉价、不可控、Dark 模式易脏 |
| 大量玻璃拟态 / 毛玻璃堆叠 | 与 Windows 原生感冲突，且性能差 |
| 卡片套卡片 | 层次失控 |
| Emoji 图标 | 跨平台渲染不一致，Windows 上过时 |
| 卡通幽灵 | Logo 要抽象，不要吉祥物 |
| 网页 Dashboard 观感（大卡片 + 大阴影 + 大留白 + 图表墙） | 这是 Windows 桌面应用 |
| AI Demo 风格 | 紫蓝渐变 + 发光按钮 + 大字标语 |

## 7. 与 Core 0.1 的边界声明

UI 0.1 **不会**：
- 重写 Scanner / Registry / 检测算法
- 修改 `EvidenceWeights`、`RiskEvaluator`、`OrphanConfidenceThresholds` 的取值
- 为了页面好看要求 Core 增加不存在的判定能力

UI 0.1 **只会**：
- 消费 Core 已有的模型与接口
- 把 Core 说不清楚的地方，登记为 `UI Data Requirement`（见 `02` 第 5 节）

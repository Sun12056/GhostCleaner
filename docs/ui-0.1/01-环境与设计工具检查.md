## 4. 本次 UI 0.1 的实际执行策略（替代方案 + 理由）

方案要求「Figma 负责 Final Design System + Final UI」。在当前环境无 Figma 接入的前提下，为**不阻塞与 Core 0.1 的同步开发**，采用等价替代：

| 原方案环节 | 替代交付物 | 等价性说明 |
|---|---|---|
| Figma Design Tokens 变量 | `07-DesignTokens.md` + `prototype/css/tokens.css`（CSS 自定义属性） | CSS 变量与 Figma Variables 一一对应，UI 0.2 可直接映射为 WPF `ResourceDictionary` |
| Figma Components / Variants | `09-组件规范.md` + `prototype/css/components.css` | 每个组件列出全部 State / Variant，UI 0.2 直接映射为 `ControlTemplate` |
| Figma 页面画板 | `10-页面设计.md` + `prototype/index.html` | 逐页面标注尺寸、栅格、字号、颜色 token |
| Figma Prototype（可点击） | `prototype/index.html`（hash 路由 SPA，Light/Dark 可切换） | 可点击、可走查，覆盖方案要求的全部核心流程 |
| Figma Dev Mode Handoff | `15-UI-0.2-开发交接.md` | 含页面尺寸、间距、字体、颜色、组件状态、动效、数据需求 |

> **结论**：设计资产以「Markdown 规范 + 可运行 HTML 原型」形式交付，全部可版本管理、可 Diff、可被 UI 0.2 直接消费。
> **后续建议**：若之后接入 Figma MCP，可由 `15-UI-0.2-开发交接.md` 反向生成 Figma 文件，无需重做设计。

## 5. 安装建议（不阻塞本次执行）

按优先级，如果后续要补齐设计链路：

1. **Figma MCP / Connector**（唯一能真正产出 `.fig` 的路径，需用户提供 API Token）
2. **Desktop Application UI Skill**（WPF/WinUI/Fluent 规范，对 UI 0.2 实现帮助最大）
3. **Accessibility / UX Review Skill**（用于 UI 0.1 结束后的对比度与键盘可达性走查）

本次不为了凑数安装「只会生成网页 Landing Page / React 网站 / Webflow / 营销站」的 Skill —— GhostCleaner 是 **Windows Desktop Application**，不是 Web SaaS Dashboard。

## 4. 现有 UI 的主要问题（UI 0.1 要解决）

| # | 问题 | 证据 | 严重度 |
|---|---|---|---|
| 1 | **产品名与仓库名不一致** | 窗口标题/侧栏/文档全是 `WinCleaner`，仓库是 `GhostCleaner` | 高 |
| 2 | **扫描与结果混在一个巨型页面** | `OrphanScanView.xaml` 20.9 KB、`OrphanScanViewModel.cs` 703 行，配置/进度/结果/详情/清理全挤在一起 | 高 |
| 3 | **没有独立「扫描结果」页** | 扫描完仍在扫描页里看结果，无法回到结果复查 | 高 |
| 4 | **进度计算错误** | `ProgressValue = ScannedDirectories * 100 / CandidateCount` —— 分子分母含义不匹配，`CandidateCount` 是候选数不是总数 | 高 |
| 5 | **没有暂停** | 只有 `Stop()`（Cancel），方案明确要求「暂停 / 取消」 | 中 |
| 6 | **只有 Light 模式** | `Colors.xaml` 硬编码单一套 Brush | 中 |
| 7 | **无图标系统** | 导航纯文字；证据用 `✓` `⚠` 字符（`Evidence.IconText`） | 中 |
| 8 | **无 Design Token 体系** | `Colors.xaml` 是平铺 Brush，无语义命名层级（无 Surface/Elevated/Border-Subtle 之分） | 中 |
| 9 | **卡片靠 `DropShadowEffect`** | 每卡片一个 `DropShadowEffect`，既不像 Windows 原生，也有性能开销 | 中 |
| 10 | **DataGrid 直接裸用** | 只改了配色，未定义行高/悬停/选中/斑马纹/空状态 | 中 |
| 11 | **无 Empty / Loading / Error / Permission 状态设计** | 只有 `StatusText` 一个字符串承载所有状态 | 高 |
| 12 | **无「扫描记录」** | 刷新页面即丢失本次扫描结果，无法回看 | 中 |
| 13 | **无结果详情面板** | 详情靠 DataGrid 展开/字符串罗列（`EvidenceText` 拼成一大段） | 高 |
| 14 | **侧栏导航无图标、无分组** | 8 项平铺，含与 Core 0.1 无关的页面 | 中 |
| 15 | **按钮无 Hover / Pressed / Focus 视觉** | `BaseButton` 只有 `IsEnabled=False → Opacity 0.45` | 中 |
| 16 | **无键盘焦点可见态** | 全应用未定义 FocusVisual | 中 |
| 17 | **「开始扫描」入口弱** | Dashboard 上 4 个按钮同权重（开始扫描 / 打开隔离区 / 打开设置 / 刷新） | 高 |
| 18 | **数字无等宽对齐** | 大小/百分比用普通字体，列表竖向不对齐 | 低 |
| 19 | **窗口非 Fluent** | 系统标题栏 + 直角窗体，无 Mica/圆角/暗色标题栏支持 | 低（UI 0.2 处理） |

## 6. 一条重要判断

> **现有 UI 最大的问题不是"不好看"，而是"扫描流程没有被设计成一个流程"。**
>
> 配置、进度、结果、详情、清理五个阶段被压缩进同一个页面，导致：
> - 用户扫描时必须盯着一个 703 行 ViewModel 驱动的长页面；
> - 扫描完成后无法回到「上次结果」复查；
> - 证据被拼成一段字符串，用户看不到「为什么这么判断」。
>
> 这正是 UI 0.1 要解决的核心：**把一条流程拆成四个有明确主任务的页面。**
